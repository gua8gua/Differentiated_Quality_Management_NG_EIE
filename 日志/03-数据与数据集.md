## 0. 结论摘要（先读）

| 维度 | 结论 |
|---|---|
| **数据形态** | 以**多变量时序 + 结构化业务表 + 半结构化日志/报告 + 图像/波形**为主，辅以**知识三元组**；无单一格式可覆盖全项目 |
| **标准底座** | **ISO 8000**（质量三维）+ **GB/T 34960.5**（治理）+ **ISO 13374/OSA-CBM**（PHM 功能块）+ **IEC 62424/OPC UA**（过程数据互操作） |
| **开源数据** | **无**与「电子信息装备全生命周期质控」完全对齐的公开集；需**分场景拼装**：PHM 轴承/IMS、SECOM 高维工艺、MVTec 视觉、MIMII 声学、OPC UA 仿真/HAI 等 |
| **语义工作** | 先做**元数据目录 + 领域本体 + 编码/交换规范**，再支撑 Neo4j 与 RAG；交付物应对齐 P1「数据目录文件」与结题「2 项标准规范草案」 |
| **当前缺口** | 申报书已注明**尚无真实装备数据集**；P1–P3 必须并行推进**标准草案 + 开源基准验证 + 合作单位脱敏数据**三条线 |

## 一、任务所需数据类型评估

### 1.1 按申报书全生命周期梳理

申报书要求覆盖：**设计 → 研制 → 生产 → 装配 → 试验 → 交付 → 运行 → 维护 → 保障**，并汇聚以下多源异构数据（2.1.1 节）：

| 生命周期阶段 | 典型数据内容 | 数据形态 | 对应方法/实验 |
|---|---|---|---|
| 设计/论证 | 需求文档、FMEA、设计规范、指标分解 | 非结构化文档、表格 | 域 A 标准；域 D NER/关系抽取 |
| 研制/生产 | 工艺参数、批次、装配记录、AOI/检测图像 | 时序 + 结构化 + 图像 | 域 B 治理；域 E 缺陷预测 [31][34] |
| 试验/验收 | 试验曲线、波形、环境适应性记录 | 时序、波形文件 | 域 B 补全；域 E 健康度 [28][32] |
| 交付/运行 | IoT/SCADA 监测、运维日志、状态数据 | 高频时序、日志 | 域 B 异常检测 [08][11]；域 E RUL |
| 维护/保障 | 维修报告、故障截图、处置案例、专家评注 | 文本、图像、半结构化 | 域 D 图谱增量；域 E RAG [30] |
| 标准/规范 | 国标、国军标、企业质控规程 | 文本、PDF | RAG 语料；本体约束 |

## 二、常见数据格式

### 2.1 按存储与交换分层

| 层级 | 常见格式 | 本项目用途 |
|---|---|---|
| **采集原始层** | CSV、TXT、TDMS、WAV、二进制流、OPC UA NodeId 序列 | 接入感知层；需映射到统一 schema |
| **治理加工层** | Parquet、HDF5、NPZ、Feather | 实验一流水线中间产物；带置信列 |
| **业务结构化层** | MySQL 表、JSON/JSONL、XML | 主数据、指标字典、权限、流程 |
| **文件对象层** | FastDFS / S3 对象 + 文件 ID | 图像、PDF、大波形 |
| **图谱层** | Neo4j CSV 导入、RDF/Turtle（可选）、Cypher | 质控知识图谱 |
| **向量检索层** | FAISS/Milvus 向量 + 元数据 JSON | RAG 语料块 |
| **模型输入层** | Tensor `.pt`、NumPy、GAF/MTF 图像张量 | 域 E 深度学习 |
| **交换与标准层** | XML（ISO 8000-110 系）、eOTD-q/r-xml、JSON-LD | 对外交换、主数据请求/响应 |

### 2.2 推荐的项目内部「Canonical 格式」（建议在域 A 规范中定义）

为打通 B→D→E，建议统一**逻辑模型**（物理格式可多种）：

```yaml
# 质量时序记录（逻辑 schema 示例）
equipment_id: string          # 装备/批次唯一标识
sensor_id: string
timestamp_utc: ISO8601
feature_vector: float[]       # 已 Z-score 或归一化
quality_flag: enum            # normal | anomaly | missing_imputed
confidence_lower: float?      # 共形预测下界（可选）
confidence_upper: float?      # 共形预测上界（可选）
provenance:                   # 溯源（FAIR + ISO 8000 语用质量）
  source_system: string
  ingest_time: ISO8601
  governance_version: string
```

```yaml
# 质量知识三元组（逻辑 schema 示例）
subject: uri | string         # 如 元器件:批次xxx
predicate: string             # 如 导致、符合、属于
object: uri | string
source_doc: string            # 溯源文档 FastDFS ID
confidence: float
```

## 三、相关标准体系

### 3.1 标准总览与在本项目中的角色

| 标准/框架 | 核心内容 | 本项目对应 | 验证方式 |
|---|---|---|---|
| **ISO 8000** | 句法/语义/语用质量；可携带质量证据的便携数据 | 1.1 质量数据描述规范 | 三维检查清单；主数据 XML 一致性 |
| **ISO 8000-110 系** | 主数据特征数据交换（语法、语义编码、一致性） | 跨企业/跨系统交换接口 | eOTD 类编码或自建字典引用 |
| **GB/T 34960.5-2018** | 数据治理规范（国内） | 1.1 管理标准规范 | 治理流程与组织职责对照 |
| **IEC 62424** | 过程工业数据表达 | 过程装备/产线数据 | 数据元与过程标签映射 |
| **IEC 62541 / OPC UA** | 工业互操作、信息模型、时序 | IT-OT 集成、传感器语义 | NodeSet、与 KG 节点对齐 |
| **ISO 13374 / MIMOSA OSA-CBM** | DA→DM→状态→健康→预后→建议 | 平台分层与 PHM 闭环 | 功能块与模块映射表 |
| **ASME Y14.5 / ISO GPS** | 几何基准 Datum | 精密装备几何质量 [07] | 点云—基准关联元数据 |
| **ISA-95 / IEC 62264** | 企业—制造活动模型 | 产线—MES—装备层级 | 资产模型与 equipment_id 对齐 |
| **FAIR** | 可发现、可访问、可互操作、可重用 | 数据集发布、论文复现 | 元数据目录 + DOI/版本 |
| **PROV** | 数据血缘与溯源 | 治理流水线、补全记录 | provenance 字段 |
| **QUADAS-3 / QUAIDE** | AI/诊断研究质量评估 | 评价「模型与流程」本身 | 评测检查表 [22][24] |

### 3.2 ISO 8000 三维质量 → 本项目五维评价映射

申报书数据质量评价常用五维（正确性、完备性、时效性、一致性、可解释性），与 ISO 8000 可建立如下映射，便于写标准草案：

| ISO 8000 维度 | 本项目五维 | 可自动化验证示例 |
|---|---|---|
| 句法质量 | 一致性 | Schema 校验、编码、单位 |
| 语义质量 | 正确性 | 对照术语库/本体、值域检查 |
| 语用质量 | 可解释性、时效性 | 用户评注、SLA、溯源完整 |
| （扩展） | 完备性 | 缺失率、补全置信覆盖率 |

### 3.3 语义层：开放技术字典与本体（标准生态，非业务数据集）

ISO 8000-110 推荐语义编码引用**开放技术字典（OTD）**。工程上常用：

| 资源 | 说明 | 用途 |
|---|---|---|
| **ECCMA eOTD** | ISO 22745 兼容开放技术字典 | 主数据请求/响应语义编码参考 |
| **IOF MRO Ontology** 等制造本体 | 制造领域 OWL 本体 | 领域本体扩展基座 |
| **OPC UA Companion Spec** | 行业信息模型 | 传感器/设备语义节点类型 |
| **PROV-O** | W3C 溯源本体 | 数据血缘记录 |

> 说明：上述为**语义标准资源**，不是训练用数值数据集，但对域 A「语义互操作」必不可少。

## 一、调研结论摘要

1. **本地 `datasets` 无雷达专用数据**；最贴近元器件/电子制造的是 `01_tabular_secom`（半导体工艺质量表）。
2. **公开网络**可补充雷达 Raw ADC/IQ、SAR、4D 雷达张量，以及电子元器件退化、PCB/IC 视觉缺陷、软件缺陷预测等数据。
3. **任务书未使用「电子设备」一词**，统一表述为 **「电子信息装备」**；核心应用对象明确为 **新型雷达、软件化电子信息系统、高端基础元器件**，管控维度为 **整机 / 软件 / 元器件**。
4. 公开数据集主要用于 **算法预研与平台原型验证**，不能替代合作单位脱敏的真实装备质量数据。

## 四、网络公开候选数据集

### 4.1 雷达方向（优先看质量管控相关性，而不是目标检测性能）

> 说明：公开雷达数据集中，相当一部分是为**目标检测、语义分割、目标识别**服务的。这类数据可以用于学习雷达数据形态和算法预处理，但与本项目的“质量管控、风险识别、根因追溯、状态退化”只存在间接关系。真正优先的数据应包含：雷达硬件/传感器异常、工况扰动、故障标签、健康状态、维修/测试记录、环境状态或可构造质量风险的运行时序。

| 数据集 | 模态 | 原始任务 | 与质量管控的关系 | 质量管控贴合度 | 获取链接 |
|--------|------|----------|------------------|----------------|----------|
| **Rad-R** | 77GHz Raw ADC/IQ、RD/RA/微多普勒、IMU/温度/GPS/相机 | 雷达硬件故障鲁棒性、故障分类、严重度识别 | 直接包含雷达硬件故障/严重度/多传感器状态，可用于“雷达质量风险检测、健康状态评估、异常根因线索” | **高** | https://huggingface.co/datasets/gtaxcenter/radr |
| **Radar I/Q Machinery Imbalance** | 24GHz CW 雷达 I/Q 时序 | 旋转机械不平衡故障诊断 | 不是雷达装备自故障，但体现“雷达非接触式质量检测/设备状态监测”，可借鉴 I/Q 时序异常与故障分级方法 | **中-高** | https://ieee-dataport.org/documents/radar-iq-data-machinery-imbalance-detection |
| **RaDICaL** | 77GHz FMCW Raw ADC、RGB-D、IMU | 雷达信号处理、目标检测、多传感器融合 | 有原始 ADC 和同步传感器，适合构造“环境扰动、传感器一致性、数据质量评价”实验，但缺少装备质量故障标签 | 中 | https://databank.illinois.edu/datasets/IDB-3289560 |
| **RADIal** | 高分辨率雷达 ADC、RA/RD/点云、相机、LiDAR、GPS/CAN | 车载雷达检测、分割、多任务学习 | 可用于雷达数据治理、多模态一致性、恶劣场景下数据质量分析；目标检测本身不是质量管控目标 | 中 | https://github.com/valeoai/RADIal |
| **K-Radar** | 4D 雷达 RAED 张量、LiDAR、相机、RTK-GPS | 恶劣天气 4D 雷达目标检测 | 可用于“环境条件对雷达数据质量/模型稳定性的影响”分析；更偏感知鲁棒性，不直接给出雷达装备质量故障 | 中 | https://github.com/kaist-avelab/K-Radar |
| **CARRADA** | 相机 + 汽车雷达 RAD 张量、RA/RD 标注 | 雷达语义分割、跟踪、雷视融合 | 可做雷达张量预处理、标注结构学习、多模态数据治理；质量管控相关性较间接 | 中-低 | https://arthurouaknine.github.io/codeanddata/carrada |
| **MSTAR** | X-band SAR 图像 | SAR 目标识别 | 主要用于 SAR 目标分类，和装备质量管控关系弱；可作为雷达图像模态入门数据 | 低 | https://www.sdms.afrl.af.mil/index.php?collection=mstar |
| **ATRNet-STAR** | 大规模 SAR 目标图像 | SAR 检测/分类/生成 | 主要用于 SAR 识别/生成，适合学习雷达图像算法，不适合作为质量管控主数据 | 低 | https://github.com/waterdisappear/ATRNet-STAR |
| **OpenSARShip 2.0** | Sentinel-1 SAR 船舶 + AIS | SAR 船舶识别 | 遥感 SAR 目标解释数据，和雷达装备质量、软件质量、元器件质量关系较弱 | 低 | https://opensar.sjtu.edu.cn/DataAndCodes.html |
| **DIAT-µSAT** | X-band 微多普勒谱图 | 无人机目标分类 | 可学习微多普勒谱图表示；质量管控相关性主要限于“信号质量/分类鲁棒性” | 低 | https://ieee-dataport.org/documents/diat-msat-micro-doppler-signature-dataset-small-unmanned-aerial-vehicle-suav |

### 4.1.1 雷达质量管控更需要的数据类型

| 数据类型 | 对应质量问题 | 公开数据替代/近似 | 真实项目中应争取的数据 |
|----------|--------------|-------------------|------------------------|
| 雷达自检/BIT日志 | 收发通道异常、温漂、校准失败、链路异常 | Rad-R 的硬件故障标签可部分替代 | 雷达开机自检、周期自检、故障码、告警码 |
| 雷达原始信号质量指标 | 噪声抬升、杂波异常、通道失衡、相位漂移 | Rad-R、RaDICaL、RADIal 的 ADC/IQ 可用于构造指标 | I/Q、RD/RA图、通道幅相一致性、SNR、杂波统计 |
| 环境与工况数据 | 高低温、湿度、振动、电磁干扰导致质量波动 | K-Radar 的天气场景、Rad-R 的温度/IMU | 温度、湿度、振动、电源、电磁环境、任务剖面 |
| 维修与处置记录 | 故障根因、处置策略、复发问题 | 无直接公开替代 | 维修单、质量问题单、专家处置意见、复测结果 |
| 软件运行与版本记录 | 接口异常、算法退化、版本引入缺陷 | PROMISE/Defects4J/CodeXGLUE 仅可迁移软件质量方法 | 雷达软件日志、版本变更、测试用例、缺陷单、回归测试结果 |
| 元器件批次与老化数据 | 批次缺陷、参数漂移、寿命退化 | SECOM、NASA Capacitor/MOSFET/IGBT | 元器件来料检验、筛选试验、老化试验、批次追溯 |

## 五、建议下载与使用顺序

### 5.1 按任务书三类对象

| 对象 | 优先数据集 |
|------|------------|
| **雷达（整机）** | 优先 `Rad-R demo`；再用 `RaDICaL` / `RADIal` 构造信号质量、环境扰动、多模态一致性实验；`K-Radar` 可用于恶劣天气下数据质量/模型稳定性分析；`MSTAR`、`ATRNet-STAR` 仅作雷达图像算法入门，不作为质量管控主数据 |
| **软件** | PROMISE/NASA MDP → CodeXGLUE Defect Detection →（需可复现实验）Defects4J |
| **元器件** | 本地 SECOM → NASA Capacitor/MOSFET/IGBT → DeepPCB / SolDef_AI / MIIC |

### 5.2 按项目阶段

1. **P1–P4（数据治理）**：SECOM、C-MAPSS、合成 MCDM、mfg009
2. **P5–P6（知识图谱与风险）**：SAREF/IOF + 后续自建雷达质控语料；Rad-R/RADIal 做雷达信号异常
3. **P7–P8（智能体与平台）**：IIoT/HAI 风格时序 + 三类对象各自代表数据集联调
