# §2.3–2.5 平台工程与智能体系统

> 申报书章节：**§2.3 三类质量管控智能体 + §2.4 反馈评测 + §2.5 平台研发** | 主要来源：申报书 + 论文 [03][26][29]

---

## 1. 这个领域在学什么

把 L1–L5 的能力**集成到可运行的软件平台**上，形成申报书 **§2.5** 所述闭环：

```
质量数据汇聚 → 质控知识图谱构建 → 质量风险检测 → 质量风险智能分析
→ 质量问题协同处置 → 装备质量持续优化
```

---

## 2. 核心概念

### 2.1 平台分层（申报书 2.5，见图18）

![图18 智能决策管理平台架构](../../../资料/img/18_质量管控智能决策管理平台架构.jpeg)

申报书原图为 **六层**：感知层（雷达/软件/元器件）→ 治理层（检测、归一化、增强、补全、评价）→ 垂类模型层（领域知识 + DeepSeek/Qwen）→ 智能体层 → 风险识别/检测/预测层 → 应用层（任务下发—处置—反馈）。

简化四层对照：

```
应用层（智能决策、三类智能体、预警处置）
  ↓
知识层（质控知识图谱、垂类模型、RAG）
  ↓
治理层（§1.2 数据治理、§1.3 质量评价）
  ↓
感知层（IoT、MES、试验系统采集）
```

### 2.2 混合存储（申报书 2.1.1）

- **Neo4j**：质控知识图谱实体与关系。
- **MySQL**：主数据、字典、权限、业务日志、文件索引。
- **FastDFS**：报告、图像、波形等大文件。
- **向量库**（Milvus/FAISS 等）：RAG 检索（2.2.3 扩展实现）。

### 2.3 数据闭环

1. 标准定义数据格式（§1.1 / L1）
2. 治理清洗入库（§1.2 / L2）
3. 质量评价反馈（§1.3 / L3）
4. 图谱与风险分析（§2.1–2.2 / L4–L5）
5. 智能体协同处置（§2.3 / L6）
6. 响应评测与反哺（§2.4 → 更新 §1 标准与 §2.1 图谱）

### 2.4 三类质量管控智能体（申报书 2.3）

| 智能体 | 对应章节 | 核心目标 |
|---|---|---|
| **整机**质量管控智能体 | 2.3.2 | 质量指标分解、**全局决策共享** |
| **软件**（系统）质量管控智能体 | 2.3.3 | **耦合稳定、风险可溯**（FCT） |
| **元器件**质量管控智能体 | 2.3.4 | **质量可控、机理可释**（PFP） |

**群智质量决策**（2.3.1）：Top-Down 指标分解 + Bottom-Up 风险涌现；四端（研发/制造/试验/运维）与四环境（特征提取/知识图谱/风险预测/预警触发）协同；冲突时用 **博弈论 + 共识算法** 消解。

![图14 三类智能体协同机制](../../../资料/img/14_三类质量管控智能体协同机制.jpeg)

![图15 整机智能体结构](../../../资料/img/15_整机质量管控智能体结构.jpeg)

整机智能体以 **PRL**（性能达标、可靠性保障、寿命预测）为底层需求，通过指标分解与约束下发驱动全局决策共享。

![图16 软件智能体结构](../../../资料/img/16_软件质量管控智能体结构.jpeg)

软件智能体以 **FCT**（功能完整、耦合稳定、拓扑可溯）为核心，强调接口耦合、功能逻辑、信号传输、边界效应四类运行环境。

![图17 元器件智能体结构](../../../资料/img/17_元器件质量管控智能体结构.jpeg)

元器件智能体以 **PFP**（物理合规、失效可预、质量稳定）为核心，含微观检测/缺陷筛选与参数监测环境，支撑机理可释要求。

> 注意：「系统质量管控智能体」= **软件**侧，不是泛指的硬件子系统。

### 2.5 工程实践
